Rotation-Based Classroom Project

An Iterative Group Activity to Build Shared Lab Reports

Author

Scott J. LaCombe

Published

February 12, 2026

Keywords

reproducibility, data visualization, file paths, working directories, collaboration

Teaching Materials » Modules » Rotation-Based Classroom Project

NoteOverview

As a “capstone” project for the course, students will work in small groups to produce a report documenting a data set of their group’s choosing. Their job is to identify a dataset and then summarize and visualize key elements of the data in a written report. Each group member selects a separate dataset, but each stage of the project involves sending their data and code to another group member, who completes the next task. The report is gradually completed over several weeks, with students completing one task at each phase and then sending the work to another student. After 5 weeks, all group members will have seen and shared everyone’s reports. By sending the report to other students and requiring that all code runs on someone else’s computer, students can actively learn about file paths and working directories, as well as software dependencies.

Motivation and Learning Goals

  • Goal 1: Learn how to write code and organize data in a way that is reproducible.
  • Goal 2: Understand how to collaborate with others on a project involving data analysis.
  • Goal 3: Learn how to critically evaluate and explore sources of data.
WarningContext for Use

This project is designed for introductory courses that use a programming language. While it is written for R users, it could easily be adapted to other software as well. It is mostly asynchronous, and could be used for in-person or online learning. Group sizes can vary from three to five. It is designed to take place over 6 weeks, with work completed at home with the exception of week 6, which would require a lab day for group discussion:

Prerequisites

No prerequisites are required, this project is designed for introductory classes. However, it is suggested that students first learn the basics of R (or whatever software they are using) before starting the project. It is designed to take place in the second half of the semester after students have learned the principles of loading data, cleaning it, and visualizing it.

Practical Tips

Provide clear expectations for role rotation and documentation early in the project. Anticipate common misconceptions about uncertainty and replication. Consider accessibility needs and provide alternative formats where appropriate.

Assessment

  • Formative: clicker questions, think-pair-share prompts, checkpoint plots
  • Summative: rubric for final figure plus a 300-word memo assessing analytic decisions
  • Answer keys / exemplars: stored with instructor materials

Variations and Extensions

Level Variations

This module can be simplified by reducing the number of analytic choices or expanded by incorporating additional datasets or modeling techniques.

Follow-ups and Links to Other Work

Learning outcomes can be reinforced through later assignments focused on replication, robustness checks, or peer review of analyses.
